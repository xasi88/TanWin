# TanWin — проектная документация

Документ для разработчика: как устроено приложение, где что лежит и как вносить изменения. Описание методики для учеников — в самом приложении («Ещё → Методика»), общий обзор — в [README](../README.md).

Что видит человек на каждом экране и по каким правилам это работает, описано отдельно — в карте функций (`docs/Карта TanWin/`: все экраны и функции приложения). Как с ней работать — в `CLAUDE.md` в корне проекта.

## 1. Что это

Статическое прогрессивное веб-приложение (PWA): HTML + CSS + JavaScript (ES-модули), без сервера, без сборщика и без внешних библиотек.

* Открывается в любом браузере по ссылке.
* Устанавливается как отдельное приложение (кнопка «Установить приложение» в меню), работает без интернета.
* Прогресс хранится на устройстве (localStorage), переносится файлом.
* Тексты Корана и учебные данные лежат в `data/`, аудио чтецов берётся с Quran.com и EveryAyah.

## 2. Слои

```
┌─────────────────────────── Экраны (js/views/*) ───────────────────────────┐
│ home · review · quran · surah · progress · more · reference · onboard      │
├──────────────── Обучение ────────────────┬────────── Оболочка ────────────┤
│ lesson.js  (плеер урока, карточки)        │ app.js   (маршруты, меню, тема)│
│ exercises.js (26 генераторов упражнений)  │ install.js (установка PWA)     │
│ path.js    (открытие уроков, награды)     │ ui.js    (DOM, иконки, окна)   │
├──────────────── Содержание ──────────────┼────────── Сервисы ─────────────┤
│ course.js  (этапы, уроки, теория)         │ store.js (прогресс, повторения)│
│ letters.js (буквы, махраджи)              │ audio.js (чтецы, звуки, запись)│
│ rules.js   (правила таджвида)             │ data.js  (загрузка данных)     │
│ diagram.js (схема речевого аппарата)      │ arabic.js (разбор текста)      │
└───────────────────────────────────────────┴────────────────────────────────┘
                 data/*.json  ←  tools/qdata (сборка из Quran.com API)
```

Правило зависимостей: **содержание** не знает про DOM; **сервисы** не знают про экраны; **экраны** собирают всё вместе. `arabic.js`, `letters.js`, `rules.js`, `course.js` работают и в Node (их использует сборка данных).

## 5. Данные

| Файл | Содержимое |
|---|---|

| `data/q/NNN.json` | Сура: для каждого аята — слова с разметкой таджвида, перевод, тайминги слов для двух чтецов |
| `data/bank.json` | 6 189 слов Корана: текст, ключ аудио, частота, уровень, транскрипция, признаки |
| `data/pairs.json` | 72 минимальные пары (слова, отличающиеся одной трудной буквой) |
| `data/rare.json` | Примеры редких правил со всего Корана |

Разметка таджвида хранится компактно: `أَحَ[qد]ٌ` — буква `د` с правилом `q` (калькаля). Коды — в `rules.js`.

Уровни слов (`arabic.js → levelOf`): `fatha → kasra → damma → tanween → madd → sukun → shadda → full`. Слово попадает на уровень, если в нём нет ничего из следующих этапов, — так упражнения используют только пройденное.

Пересборка данных: `node tools/qdata/fetch.mjs`, `node tools/qdata/fetch_seg.mjs`, `node tools/qdata/build.mjs`. Скачанные «сырые» файлы (`tools/qdata/raw`, `seg*`) в репозиторий не входят.

## 6. Уроки и упражнения

Урок в `course.js` — список шагов:

```js
{ id: "5.1", title: "Фатха  ـَ", sub: "Звук «а»", steps: [
  card("Заголовок", ["Абзац с {арабским} и **жирным**"], { big: "بَ تَ", wordsLevel: { level: "fatha", n: 4 } }),
  { t: "letter", id: "ba" },            // отдельная буква и её название
  { t: "forms", id: "ba" },             // та же буква в начале, середине и конце слова
  { t: "blend" },                       // «слог + слог = слово» из букв урока (или { vowels, need, n, maxLen })
  { t: "rule", code: "q" },             // карточка правила с примерами из Корана
  ex("readWord", 5, { level: "fatha" }),// 5 вопросов генератора readWord
  q("Вопрос?", ["верный", "неверный", "неверный"], "пояснение"),
  { t: "read", level: "fatha", n: 8 },  // беглое чтение с самопроверкой
  { t: "speak", level: "fatha" },       // запись голоса и сравнение с чтецом
]}
```

Генераторы (`exercises.js`): `letterName`, `letterPick`, `letterListen`, `sylListen`, `blend`, `formWhere`, `shape`, `listenFirst`, `pairListen`, `zonePick`, `pointPick`, `heavy`, `formPick`, `firstLetter`, `hasLetter`, `syllable`, `syllableRev`, `readWord`, `listenWord`, `match`, `ruleSpot`, `ruleName`, `maddCount`, `nunRule`, `sunMoon`, `allahLam`, `raRule`, `waqfForm`, `stopSign` + вопросы `quiz`.

Каждый вопрос имеет ключ повторения (`L:ba`, `W:madd`, `R:f`…). Ответ обновляет коробку Лейтнера в `store.js`; раздел «Практика» строит повторение из просроченных ключей (`views/review.js → stepFor`).

**Порядок этапов** (с 1.11.0): 1 первые шаги → 2 алфавит: буквы → 3 алфавит: формы → 4 огласовки (фатха, касра, дамма, сукун, танвин) → 5 слоги → 6 слова → 7 слова с маддом, сукуном, шаддой → 8 аяты и особые написания (после проверки 8.7 открываются суры) → 9 махраджи → 10–13 таджвид и вакф → чтение сур. Каждый этап добавляет одно новое. Раньше номера уроков были другими: `LESSON_MOVES` в `store.js` переносит сохранённый прогресс (и старые файлы экспорта) на новые номера; признак — поле `course` в состоянии.

Слова с сукуном в банке относятся к уровню `sukun`, который допускает танвин и мадд; в уроках, где сукун идёт раньше них (4.5, 5.4), такие слова отсекаются параметром `avoid: "TAmgySL"` (коды признаков — `FEAT` в `tools/qdata/build.mjs`).

**Буквы, слоги, слова** (`syllables.js`). `letterIntro` (этап 2: отдельная буква и её название; полная карточка с махраджем — по ссылке «Подробнее») → `letterForms` (этап 3: буква в начале, середине и конце слова) → плитки-слоги `syllTile` / `harakatTiles` (этап 4: буква с огласовкой, со звуком) → `blendCard` (этап 5: «слог + слог = слово»). Примеры для сложения подбирает `blendsFor()`: настоящие слова Корана из одних открытых слогов и только из уже пройденных букв (`knownLetters()` в `course.js`), а пока букв мало — цепочки слогов. Слоги звучат записями из `audio/letters` (`playSyll`, `playLetter`, `playSeq` в `audio.js`), целое слово — голосом чтеца. Упражнения: `letterListen` (буква на слух), `sylListen` (слог на слух), `blend` (собрать слово из плиток-слогов — `blendBoard`).

**Замена озвучки букв.** Файлы `audio/letters/<id>.mp3` (название буквы) и `<id>-a|i|u.mp3` (слоги); `id` — из `letters.js`. Свои записи достаточно положить с теми же именами (или прогнать через `node tools/audio/build.mjs <папка>`), затем `node tools/build.mjs`.

**Как добавить урок:** дописать объект в нужный этап `course.js` → проверить в браузере → `node tools/build.mjs`.

## 7. Прогресс

**Тема.** `settings.theme`: `auto` (по умолчанию, в настройках — «Как на устройстве») — светлая, а при тёмной теме системы — тёмная (`prefers-color-scheme` в `css/app.css`); `light` и `dark` задают тему явно через атрибут `data-theme` (`applySettings()` в `app.js`).

`localStorage["tanwin.v2"]`: профиль (имя, цель дня), настройки, уроки (звёзды, лучший результат), суры, опыт по дням, серия, повторения, статистика, награды. Урок открыт, если пройден предыдущий или сдана проверка этапа. Настройка «Открыть все уроки» (`settings.unlockAll`) открывает всё сразу — для тех, у кого прогресс потерялся; «Продолжить» тогда ведёт к первому непройденному уроку после самого дальнего пройденного.

**Два окна — одно хранилище** (с 1.22.1). Две вкладки приложения (или вкладка и установленное приложение) делят `tanwin.v2`, а `store.js` держит прогресс в памяти и записывает его целиком. Поэтому перед любым изменением окно берёт из хранилища то, что успело записать другое (`pull()`), а каждое изменение записывает сразу: несохранённого в памяти не бывает (`srsSeen` и `hardSeen` тоже сохраняют). Чужую запись окно подхватывает по событию `storage`, при возвращении к нему (`visibilitychange`, `pageshow`) и при переходе между экранами (`store.sync()` в `route()`). Данные переносятся в тот же объект (`adopt`), поэтому ссылки на `store.get()` и его части остаются живыми. Пустое хранилище чужой записью не считается: копия из памяти записывается заново. Менять прогресс можно только через `store.set()` и функции `store.js` — прямое присваивание в `store.get()` потеряется. Остаётся редкая гонка: два окна записали в пределах нескольких миллисекунд — сохраняется более поздняя запись. Проверка: `node tools/audit/shared-data-check.mjs` (нужен сервер на 8765).

## 7а. Арабский текст

- **Размер.** Две независимые настройки: `settings.uiScale` (весь текст приложения, через `font-size` у `html` — все размеры в `rem`) и `settings.arScale` (арабский, 80–240%). Все арабские надписи — класс `.ar`: `font-size = --s × --ar-k × --fit`, где `--ar-k = arScale ÷ uiScale` (так арабский не зависит от размера остального текста). `--s` задаёт компонент, `--fit` — автоподгонка. Значки и заголовки (узлы пути, названия сур) ставят `--ar-k: 1` — растут вместе с интерфейсом. Кнопка «Aa» (`sizeButton()` в `ui.js`) меняет оба размера прямо в уроке и читалке.
- **Не вылезать за рамки.** `fitArabic()` (`ui.js`) после каждой отрисовки, поворота экрана и смены масштаба уменьшает `--fit` у слов, которые не помещаются в свою карточку или кнопку. Арабские слова никогда не переносятся посередине.
- **Выбор шрифта.** `settings.arFont` — один из четырёх (список `AR_FONTS` в `ui.js`); у кого настройки нет, действует `hafs`:

  | Ключ | В настройках | Шрифт | Файл | Лицензия |
  |---|---|---|---|---|
  | `hafs` (по умолчанию) | Мадина | KFGQPC Uthmanic Script Hafs, версия 18 — шрифт печатного мусхафа Мадины | `fonts/hafs.woff2` | Комплекс имени короля Фахда; файл не изменён |
  | `amiri` | Амири | Amiri Quran (с исправленными метриками, см. ниже) | `fonts/amiri-quran.woff2` | OFL |
  | `scheherazade` | Шехерезада | Scheherazade New (SIL) | `fonts/scheherazade.woff2` | OFL |
  | `noto` | Ното | Noto Naskh Arabic | `fonts/noto-naskh.woff2` | OFL |

  Переключатели — «Ещё → Вид → Арабский шрифт» и панель «Aa» (`sizePanel` в `ui.js`: урок, читалка, страница мусхафа, режим чтения). `applySettings()` кладёт выбранное семейство в CSS-переменную `--ar-font`, на которую опирается класс `.ar`; после загрузки файла заново вызывается `fitArabic()`. Номера аятов, анимация написания буквы и схема махраджей всегда набраны Amiri Quran. Все файлы лежат в `fonts/` и входят в офлайн-кэш; браузер скачивает шрифт, только когда он выбран.
- **Метрики новых шрифтов.** Вёрстка рассчитана на метрики Amiri Quran (+1.40/−0.80 em). Сами файлы новых шрифтов не меняем (KFGQPC этого не разрешает, у OFL-шрифтов зарезервированы имена), поэтому метрики задаются в `@font-face` (`css/app.css`): `ascent-override: 140%`, `descent-override: 80%`, `line-gap-override: 0%`, а видимый размер выравнивается через `size-adjust` (Ното 91%). У Шехерезады знаки над и под буквой уходят дальше, чем у остальных, поэтому она уменьшена до 92% и чуть сдвинута вверх (132% / 88%) — при большем размере огласовки вылезали из кнопок в уроках (проверено автопроверкой). Safari не поддерживает `ascent-override` / `descent-override` — там у этих шрифтов собственные метрики; автопроверку вёрстки на WebKit нужно запускать отдельно.
- **Знаки «не читается».** В данных кружок над непроизносимой буквой — U+06DF, вытянутый нолик — U+06E0 (в разметке таджвида Quran.com оба заменены сукуном U+06E1; `tools/qdata/build.mjs` → `fixZero()` возвращает их по обычному тексту). В шрифте «Мадина» глифа U+06DF нет, тот же кружок в нём — U+0652, поэтому `ar()` и `arParts()` при выводе заменяют U+06DF на U+0652. Одиночный знак без буквы `ar()` ставит на татвиль.
- **Как добавить шрифт.** Проверить, что в нём есть все арабские знаки из `data/` (диапазоны U+0600–06FF, U+08xx), положить `woff2` в `fonts/`, добавить `@font-face` с теми же переопределениями и подобрать `size-adjust`, дописать строку в `AR_FONTS`, прогнать `node tools/audit/audit.mjs --font <ключ>`, затем `node tools/build.mjs`.
- **Цвета таджвида при чтении.** `settings.tajweed`. В читалке, на странице мусхафа и в режиме чтения текст всегда размечен (`<span class="tj r-код">`), а при выключенной настройке цвет снимается стилем — класс `tj-off` на `<html>` (ставит `applySettings()`), поэтому переключение мгновенное и без перерисовки. Переключатели: «Ещё → Вид», кнопка «Таджвид» в панели читалки и переключатель в панели «Aa» — все идут через `setTajweed()` (`ui.js`), который синхронизирует кнопки с атрибутом `data-tj-btn`. Карточка слова (по нажатию) показывает цвета всегда. В уроках и уроках-сурах настройка, как и раньше, применяется при отрисовке шага.
- **Шрифт.** В оригинальном Amiri Quran высота строки рассчитана под знаки остановки (ascent 1.815 em), поэтому буквы «сидели» низко и их хвосты наезжали на текст ниже. `tools/font/fix-metrics.py` делает из `tools/font/amiri-quran.original.woff2` версию с метриками +1.40/−0.80 em, центрированными по реальным буквам (очертания не меняются, лицензия OFL это разрешает). Знаки остановки показываются только в сплошном тексте Корана, где межстрочный интервал это учитывает.
- **Связность букв.** Цвета таджвида — это `<span>` внутри слова. При запуске `checkShaping()` проверяет, соединяет ли браузер буквы через границу span; если нет (часть версий Safari), `arParts()` ставит границы между целыми буквами и склеивает их невидимым ZWJ.

## 7б. Страницы мусхафа, чтение, заучивание

- **Страницы.** Каждый аят в `data/q/NNN.json` хранит `[страница, строки слов…]` и джуз (из Quran.com: мусхаф Мадины, 604 страницы по 15 строк). Ни один аят не переходит на следующую страницу. В тексте — отметки «страница N · джуз M» (`pageMark`); вид «По страницам» (`ReadPage`, `#/page/N`) показывает страницу целиком, даже если на ней конец одной суры и начало другой; листание свайпом и стрелками (следующая — слева). Строки пока переносятся по ширине экрана, а не как в печатном мусхафе.
- **Место чтения.** `state.reading = { s, a, p, mode, j }` — аят у верхней четверти экрана; `mode` — `surah`, `juz` (тогда `j` — номер джуза) или `page`. Сохраняется при прокрутке и при выходе (`saveReading`). Карточка «Продолжить чтение» (`continueReading`) — только в «Моём Коране» — открывает то же место в том же виде.
- **Заучивание.** Плитка «Скрыть слова» в меню чтения скрывает треть / две трети / все слова (`renderVerses({ hifz })`); слово открывается нажатием или когда его читает чтец.
- **Трудные слова.** `state.hard` — слова, в которых ошиблись (`hardSeen`), уходят после двух верных ответов подряд; тренировка «Трудные слова» в «Практике».
- **Сохранность.** `protectStorage()` просит браузер не удалять данные; `backupDue()` раз в неделю показывает на главной «Сохраните копию прогресса».

## 7в. Полный экран и режим чтения

- **Полный экран.** Установленное приложение открывается без адресной строки само (`display: standalone` в манифесте). Во вкладке браузера страница может развернуться только по нажатию — так требуют браузеры, — поэтому `initFullscreen()` (`js/fullscreen.js`) разворачивает её при первом касании. Настройка `settings.fullscreen`: пока ученик её не трогал — включена на сенсорных устройствах в браузере; переключатель — «Ещё → Вид». iPhone полный экран для страниц не поддерживает — там только установка на экран «Домой».
- **«Мой Коран»** (`MyQuran`, адрес `#/quran`, вкладка меню). Три вида (`mqView`): главный — карточка «Продолжить чтение» (она только здесь), карточка «30 джузов» и все 114 сур по порядку мусхафа (номер, название, число аятов, место ниспослания, страница) с ручкой быстрой прокрутки справа (`surahScrub`, живёт в `body`); список 30 джузов — отдельным экраном; суры одного джуза — «Читать джуз целиком» и его суры (сура открывается с аята, с которого начинается джуз: таблица `JUZ_START`, `juzParts`). Поиска нет. Нажатие на суру сразу открывает чтение и разворачивает экран.
- **Экран чтения** (`readSession` в `views/quran.js`) один для суры (`ReadMode`), джуза (`ReadJuz`) и страницы (`ReadPage`): получает список частей `parts = [{ s, meta, data, from, to }]` и рисует их подряд; `flat` — все аяты по порядку. Нажатие на экран показывает или прячет две панели, функции в них не повторяются. **Снизу** (`.focus-bar`): автопрокрутка, её скорость и крупная «Aa» (размер, шрифт, цвета таджвида). **Сверху** (`.focus-menu`, плитки `fm-tile`, всё на виду): «Назад в „Мой Коран“» (выход; ещё — Esc и «назад» на телефоне), «Слушать» / «Остановить чтеца», суры (`surahPicker`), страница и джуз (`pagePicker`), соседние суры, закладка, закладки, чтец, темп чтеца, повтор аята, вид — «Сплошной текст» / «По аятам, с переводом» (`localStorage["tanwin.readView"]`) / «По страницам» (переход на `#/page/N`), «Скрыть слова» (заучивание), расшифровка цветов, «сура прочитана», офлайн-аудио. При открытии — только текст (класс `quiet`). Панели открывает и закрывает только нажатие на экран (`reveal` / `hide`), таймера нет; карточка слова, чтец по номеру аята и колесо страниц панели не открывают, а «пуск» автопрокрутки и чтеца — прячет их. Нажатие на номер аята — чтец читает с него. В конце джуза автопрокрутка останавливается («Джуз N прочитан», кнопка «Дальше: джуз N+1»); в конце суры и страницы — сама переходит дальше.
- **Колесо страниц** (`pageWheel`). Полоска справа с номерами 604 страниц. Жесты обрабатываются вручную (`touch-action: none`): медленное движение — 1:1 (30 px = страница), быстрое — с усилением до 14× и инерцией, так что до любого конца Корана — пара взмахов. Нажатие на номер открывает страницу, нажатие по летящему колесу останавливает его.
- **Карточка слова в режиме чтения.** Долгое нажатие на слово (≈ 0,5 с, палец не сдвинулся — иначе это прокрутка) открывает карточку слова (`wordPop`): слово читает чтец, показаны транскрипция и правила. Автопрокрутка и чтец аятов при этом останавливаются. Меню браузера по долгому нажатию и выделение текста на словах отключены.
- **Окна поверх чтения.** Любое окно (`modal()` в `ui.js`) закрывается при переходе на другой экран (`hashchange`). В чтении Esc при открытом окне или панели «Aa» закрывает только их: клавиши чтение слушает на этапе capture (`keys` в `readSession`), пока окно ещё на месте (`overlay()`). В полном экране Esc и «назад» до страницы не доходят — браузер просто выходит из полного экрана; тогда открытое окно закрывает обработчик `onFullscreenChange`, а чтение остаётся.
- **Автопрокрутка и выход.** Текст — в собственной области прокрутки; касание показывает или прячет панели. Автопрокрутка: скорость 1…20 (`localStorage["tanwin.readSpeed"]`), одно деление — 3 px/с, умноженные на размер арабского текста, чтобы темп в строках не зависел от шрифта. Пока читатель листает сам (палец, колесо, клавиши), автопрокрутка ждёт и продолжает с нового места. Экран не гаснет (`js/wake.js`: Wake Lock держится во всём приложении, пока оно на виду и было касание за последние 10 минут; при автопрокрутке и чтеце — без ограничения, `wakeWhile`). Клавиши: пробел — пуск/пауза, «+»/«−» — скорость, Esc — выход. Выход из полного экрана («назад» на телефоне) закрывает режим; место чтения сохраняется в `state.reading`. Переключатель полного экрана — в боковом меню и в «Ещё». В тексте — отметки страниц мусхафа. В конце суры — кнопка «Дальше»; автопрокрутка переходит к следующей суре сама (`resumeScroll`), короткой суре даёт время на чтение.
- **Закладки** (`views/bookmarks.js`, адрес `#/bookmarks`). `state.marks` — закладки (ставятся из верхнего меню чтения и из карточки слова), `state.markGroups` — их группы. Порядок внутри группы — порядок в `state.marks`. Ручка (`gripBtn`) есть у каждой закладки: внутри списка сдвигаются соседние строки, у края списка закладка сама переезжает в соседний (`beside`) — другую раскрытую группу или «Без группы»; при этом браузер отпускает её из-под пальца, поэтому движение слушается на окне, а захват берётся заново. Что получилось на экране, записывает `arrangeMarks` (порядок и группа разом). Цели живут в самих закладках (`mark.plan`) — см. раздел «Учёт чтения, цели закладок, чтец»; общей цели чтения (`state.readGoal`, обратный отсчёт `goalStrip()`) с версии 1.18 нет. Вкладка «Закладки» есть и в нижней панели телефона.
- **Дорожная карта** (`juzMap(page)` в `views/quran.js`). 30 точек-джузов: пройденные закрашены, текущий заполняется по доле страниц; подпись «Джуз · стр. · пройдено, осталось». Считается от места чтения (страницы), а не от отметок «прочитано». Показана вверху экрана чтения; при чтении джуза под ней — «Читаем джуз N целиком · до конца M страниц».

## 7д. Связь с разработчиком

`js/feedback.js`. Номер WhatsApp — `CONTACT.whatsapp` в `js/version.js` (пустой — кнопки нет).

- **Кнопка** `.fb-tab` — узкая полупрозрачная «закладка» у правого края, одна на всё приложение (`initFeedback()` при запуске добавляет её в `body`), поэтому видна на любом экране, включая уроки и режим чтения. Она лежит в поле страницы и не закрывает текст; под окнами и листом ответа урока не видна; в режиме чтения гаснет вместе с панелью (`body:has(.focus.quiet)`).
- **Окно** `openFeedback()`: тип сообщения (ошибка, неточность, идея, другое), текст, кнопка-ссылка `https://wa.me/<номер>?text=…`. Черновик хранится в `sessionStorage` до отправки.
- **Что подставляется само** (`where()`, `device()`): название экрана (его передаёт маршрутизатор — `setScreen()` в `route()`), в уроке — заголовок текущего шага и арабский текст на нём, в Коране — сура, аят и страница из `state.reading`; адрес `#/…`, версия, размер окна, приложение или браузер, тема, арабский шрифт, имя ученика (если указано).
- Те же окно открывают «Сообщить об ошибке» в плашке и «Написать автору» в «Ещё». Нажатие на отправку попадает в статистику как цель `feedback` (обработчик ссылок `wa.me` в `app.js`).

## 7г. Статистика посещений

Анонимная статистика для автора — через Яндекс.Метрику (`js/metrika.js`). Своего сервера нет, данные смотрятся на [metrika.yandex.ru](https://metrika.yandex.ru).

- **Включение.** Номер счётчика — `METRIKA_ID` в `js/version.js` (0 — статистика выключена, переключателя в настройках нет). Ученик может отключить её в «Ещё → Данные» (`settings.analytics`). На `localhost` ничего не отправляется: события пишутся в консоль браузера как `[Метрика] …` — так удобно проверять.
- **Что уходит.** Просмотры экранов (адреса `#/learn/3.2`, названия вида «Урок 3.2. …»), цели ниже и обобщённые параметры посетителя: сколько уроков и сур пройдено, процент курса, текущий этап, уровень, установлено ли приложение, кто учится (ученик / ученица / не указано) и обращение («ты» / «вы»). Имя ученика, записи голоса и Вебвизор (запись экрана) — нет.
- **Цели.** Чтобы они появились в отчёте «Конверсии», в настройках счётчика создайте цели типа «JavaScript-событие» с этими идентификаторами:

| Идентификатор | Когда | Параметры |
|---|---|---|
| `onboard_started` | Нажал «Начать» на первом экране знакомства | — |
| `onboard_skipped` | Нажал «Пропустить» в знакомстве | Шаг, на котором пропустил |
| `onboarded` | Прошёл знакомство | Старт — выбранная стартовая точка; кто учится, обращение |
| `lesson_started` | Открыт обычный урок (не проверка и не сура) | Урок |
| `lesson_done` | Пройден урок | Урок, точность, впервые ли |
| `test_passed` / `test_failed` | Проверка этапа сдана / не сдана | Урок, точность |

## 7д. Страницы для поисковиков

Экраны приложения живут за «#» (`#/learn/2.1`), поисковик видит их как одну страницу. Поэтому рядом с приложением лежат обычные HTML-страницы:

- **Главная.** В `index.html` внутри `#view` стоит заставка `.boot-about`: название, описание и список этапов (вписывает `tools/build.mjs` из `js/course.js`). Приложение заменяет её первым экраном.
- **Буквы.** `/alfavit/` (алфавит) и `/alfavit/<id>/` (по странице на букву) создаёт `tools/pages.mjs` при каждом `node tools/build.mjs` из `js/letters.js`, `js/course.js` и `data/bank.json`. Стили — `css/pages.css`.
- **Правила чтения и таджвид.** `/tajvid/` и по странице на каждый урок с теорией из этапов 4 и 7–13: карточки урока, правила из `js/rules.js` с примерами из Корана (`data/q`), вопросы «Проверьте себя». Адрес страницы задан в `SLUGS` (`tools/pages.mjs`): у нового урока с теорией его нужно добавить, иначе сборка остановится. Адреса не менять — на них ссылаются поисковики.
- **Статья.** `/kak-nauchitsya-chitat-koran/` — единственная страница с отдельно написанным текстом (функция `articlePage` в `tools/pages.mjs`), ссылается на страницы букв и правил.
- Папки `alfavit`, `tajvid` и `kak-nauchitsya-chitat-koran` руками не править — правьте данные урока и пересоберите. Рядом с каждой страницей лежит `js/app.js` из `tools/pages-rescue.js`: он выручает тех, у кого ещё версия приложения до 1.19 (она отвечала приложением на любой адрес).
- **Карта сайта.** `sitemap.xml` пересобирается там же; `robots.txt` — обычный файл.
- **Service worker** эти страницы не кэширует и не подменяет приложением (см. `ROOT` в `sw.js`).
- Метрика на страницах подключается отдельным коротким скриптом и уважает выключатель «Анонимная статистика» из приложения.

## 8. Офлайн и обновления

`sw.js` заранее кэширует приложение, озвучку букв и слогов (`audio/letters`, ≈ 0,4 МБ) и тексты учебных сур. Код — «сначала сеть», данные и шрифты — «сначала кэш», аудио — из кэша, если сохранено (короткие слова сохраняются при первом прослушивании, аяты — кнопкой в читалке). Новая версия не перезагружает страницу посреди урока: появляется кнопка «Обновить».

1. Изменения → проверка локально (`python -m http.server 8080`), проверка данных `node tools/content-check.mjs`, словаря обращений `node tools/speech-check.mjs` и автопроверка вёрстки: `node tools/audit/audit.mjs` (установка и варианты запуска — в начале файла). Полный набор перед выпуском: телефон 390 и 320 px, планшет `--width 820`, компьютер `--width 1280`, самый крупный текст `--ar 2.4 --ui 1.4`, Safari `--engine webkit`, остальные шрифты `--font amiri|scheherazade|noto`. Бот проходит и режим чтения (`#/read/…`). Ещё четыре проверки: карта функций — `node tools/map-check.mjs`; робот по экранам — `node tools/audit/screens-check.mjs`; общие данные двух окон — `node tools/audit/shared-data-check.mjs`; запуск, окна поверх чтения, настройка «Транскрипция» и порядок закладок — `node tools/audit/start-check.mjs`, `reading-windows-check.mjs`, `translit-check.mjs`, `bookmark-drag-check.mjs`; подсказка о звуке без связи — `sound-fail-check.mjs`; чтение и чтец — `reading-check.mjs`, `reciter-check.mjs` (двум последним и проверке общих данных нужен сервер на 8765).
2. В `js/version.js` поднять `APP_VERSION` и добавить запись в начало `CHANGELOG` — она появится в разделе «Версии».

4. `git commit` и `git push` — GitHub Pages публикует сайт автоматически.

## 10. Возможные улучшения

* Сборка с минификацией (esbuild) — ускорит первую загрузку примерно на 30–40 %; сейчас сознательно без сборщика, чтобы проект можно было править без инструментов.

## Загрузка и работа на плохой связи

- **Код — из кэша версии.** `sw.js` отдаёт страницу, скрипты и стили из кэша `tanwin-core-<версия>` (cache-first): приложение открывается сразу и не зависит от скорости сети. Обновление приходит целиком: браузер сам проверяет `sw.js`, новая версия скачивает все файлы (`grab`: по восемь, до трёх попыток на файл), подменяет старую, страница перезагружается (вне урока — сама, в уроке — по кнопке «Обновить»). На `localhost` код берётся из сети (`DEV`), чтобы правки были видны сразу; проверять кэш можно на `http://app.localhost:8765`.
- **Первая загрузка.** `tools/build.mjs` вписывает в `index.html` (между `<!--PRELOAD-->`) `modulepreload` для всех модулей запуска и первого экрана: браузер качает их параллельно, а не цепочкой.
- **Если связь оборвалась.** Данные грузятся с тремя попытками, шрифты ждём не дольше 4 с; через 8 с под заставкой появляется «Загрузка идёт дольше обычного» и кнопка «Обновить»; если данные так и не пришли — экран «Не удалось загрузить приложение» с кнопкой «Повторить». Если не запустился сам `js/app.js`, через 15 с то же самое показывает маленький скрипт в `index.html`.
- **Звук не пришёл.** `js/audio.js` сообщает подписчикам `onFail`, когда запись не загрузилась (событие `error` или отказ `play()` с `NotSupportedError`) или не начала звучать за 8 с (`SLOW`); `js/app.js` показывает одно сообщение «Звук не загружается. Проверьте интернет. Не помогло — включите или выключите VPN.» — в уроках, карточках слов и у чтеца. Прерванное (`AbortError`) и запрещённое браузером (`NotAllowedError`) воспроизведение сбоем не считается. Слова (`audio.qurancdn.com`) и аяты (`everyayah.com`, `verses.quran.com`) идут с чужих серверов; буквы и слоги — свои, из кэша.
- **Экран не гаснет** — `js/wake.js` (см. 7в).
- **Первый заход.** Service worker берёт управление страницей (`clients.claim`) без перезагрузки: `controllerchange` перезагружает страницу, только если до этого уже был другой service worker (то есть пришло обновление).
- **Совместимость данных.** Хранилище то же (`tanwin.v2`), новые поля только добавляются: `reading.j`, `reading.mode` (старые значения `mushaf` / `ayat` читаются как сура), `qread.days[день].pp` (страницы, прочитанные сегодня). Настройка «перевод в чтении» (`tanwin.readTr`) подхватывается как вид «По аятам». Старые адреса `#/quran/N/A` открывают чтение.

## Учёт чтения, цели закладок, чтец

- **Страницы.** `readPage(p)` (`store.js`) засчитывает страницу один раз за день: при переходе на следующую страницу или после 40 с на странице (`PAGE_DWELL`) — так считаются и разрозненные страницы. Время — `readTick(ms)`. Всё это видно в «Прогрессе» (`readStats`).
- **Цели — только у закладок** (`mark.plan`, `views/bookmarks.js`). Закладок с целями может быть сколько угодно. `{ k: "seq", unit: "p" | "a", n }` — читать по порядку: n страниц или аятов в день, закладка идёт вперёд. `{ k: "rep", items: [{ s, from, to }], days }` — повторять отрывок: суру, аяты, несколько отрывков, страницы (при выборе превращаются в аяты); `days` — дни недели или `null` (каждый день). `mark.done` — когда выполнена в последний раз, `mark.cur` — где остановились, не дочитав. Задаётся в настройках закладки (`markEditor`); в списке — «ждёт сегодня» / «сегодня выполнено».
- **Экран цели** (`ReadMark`, `#/mark/ID`, вид `mark` в `readSession`). На экране ровно то, что нужно прочесть (`markParts`), в конце — «Я прочитал» (`finish`): цель выполнена, счётчик целей растёт, закладка «по порядку» переезжает за прочитанное. Цель считается только здесь: обычное чтение мусхафа цели не двигает. После цели «по порядку» — «Читать дальше» (`#/mark/ID/more`): обычное чтение суры, закладка идёт следом за читателем (`follow`), назавтра ждёт там, где он остановился.
- **Старые данные.** `upgradeGoals` (`store.js`) при загрузке переносит `mark.goal` (N страниц) в план «по порядку», а общую цель `readGoal` — в закладку «Цель чтения»; `readGoal` обнуляется.
- **Чтец.** Плитка «Слушать» — в верхнем меню (вторая, после «Назад»). Нажатие на номер аята — читает подряд с него до конца открытого текста: суры, джуза, страницы, аятов цели (`listenHere`). Отметка (класс `sel`) идёт за чтецом; остановили — плитка «Продолжить с аята N» читает дальше с того же аята (`listenAll`); ничего не слушали или дослушали до конца — «Слушать суру», с начала суры на экране. Повторить один аят — в карточке слова (долгое нажатие на слово). Нажатие на «Бисмиллях» — сура с самого начала (сначала запись 1:1 — басмала, кроме сур 1 и 9).
- **Отдельного «Моего Корана» больше нет.** В версиях 1.22.0–1.22.1 папка `quran/` была вторым приложением со своим манифестом и значком (тот же `js/app.js` в режиме `QURAN_APP`). С 1.23.0 «Мой Коран» — только раздел TanWin. Чтобы у тех, кто успел поставить отдельный значок, ничего не сломалось, старый адрес открывает раздел: `sw.js` отвечает на `/quran/…` перенаправлением на `#/quran` (без сети), а `quran/index.html` делает то же для тех, у кого приложение ещё не загружено. Хранилище то же, поэтому закладки, цели и место чтения на месте. Код отдельного приложения сохранён в ветке `quran-app-archive`. Проверка: `node tools/audit/start-check.mjs`.
- **Обновления и VPN.** `checkUpdate()` (`app.js`) — кнопка «Проверить обновление» («Ещё» → «О приложении», «Версии»): `registration.update()` и сообщение о результате. Окно «Приложение обновляется само» (`updateNotice` в `app.js`) показывается каждому один раз (`localStorage["tanwin.updNote"]`) на любом экране вне урока и чтения; роботам (`navigator.webdriver`) не показывается.
- **Письмо «Что нового»** (`newsCard` в `views/home.js`, `NEWS` в `version.js`): один раз на главной тем, кто начал до обновления.
- **Проверка:** `node tools/audit/reading-check.mjs` (нужен сервер на 8765).
